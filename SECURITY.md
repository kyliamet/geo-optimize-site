# Security Policy

## Reporting a vulnerability

Do not include credentials, private repository content, unpublished customer information, or exploitable production details in a public issue.

Use GitHub's private vulnerability reporting feature when it is enabled for this repository. If it is unavailable, contact the repository owner privately through the security contact listed on their GitHub profile and include only the information needed to reproduce and assess the issue.

## Scope

Security reports may include:

- Instructions that could expose secrets or private site content.
- Unsafe handling of untrusted website or repository content.
- Authorization gaps around commits, pushes, deployments, or pull requests.
- Generated markup that creates a meaningful injection or data-exposure risk.

General GEO disagreements, outdated crawler documentation, and feature requests should use normal GitHub issues.
